# 会话规范命名

## 格式

`MMDD｜类型｜主题`

- 统一使用全角分隔符 `｜`（`U+FF5C`）。
- `MMDD`：取会话创建日期（新会话取当天），`Asia/Shanghai`（UTC+8）两位月 + 两位日。
- `类型`：只能取下列 8 个之一。
- `主题`：2-8 个字（兼容少量英文专有名词），概括诉求，**不得包含类型词**，不含标点与引号。

## 类型表

| 类型 | 适用场景 | 反例 |
| :--- | :--- | :--- |
| 功能 | 新增能力、页面、接口、命令、插件 | 不说“优化” |
| 设计 | 视觉、交互、布局、架构方案讨论 | 不含“功能” |
| 修复 | 报错、异常、故障、排查定位 | 不含“优化” |
| 优化 | 性能、体验、代码质量改善 | 不含“修复” |
| 发布 | 提交、推送、打包、上线、PR | 不含“功能” |
| 探索 | 了解代码、查资料、调研、评估 | 不含“文档” |
| 文档 | 写/改 README、注释、说明文档 | 不含“探索” |
| 研究 | 深度技术验证、实验、对比选型 | 不含“探索” |

## 判定顺序

1. 有明显故障或报错 → **修复**
2. 有明确新增能力 → **功能**
3. 只谈外观/交互/方案 → **设计**
4. 只谈变快变好但无故障 → **优化**
5. 只谈提交/上线 → **发布**
6. 只谈文档产出 → **文档**
7. 深度验证或选型对比 → **研究**
8. 其余了解性诉求 → **探索**

## 操作方式

### 1. 重命名当前会话

在 `run_command` 中执行插件脚本（自动读取 `ANTIGRAVITY_CONVERSATION_ID`）：

```powershell
node "$env:USERPROFILE\.gemini\config\plugins\session-title\scripts\set-title.mjs" "MMDD｜类型｜主题"
```

- 默认幂等：若当前 `annotations.title` 已符合 `MMDD｜类型｜主题` 格式，脚本会跳过写入。
- 若用户明确要求重命名一个已符合规范的会话，追加 `--force`：

```powershell
node "$env:USERPROFILE\.gemini\config\plugins\session-title\scripts\set-title.mjs" "MMDD｜类型｜主题" --force
```

### 2. 检查或重命名其他历史会话

1. 通过 `ConversationService/ListConversations` 获取近期会话列表及各自的 `id`、`metadata.createTime`、`annotations.title`、`state.summary`。
2. 根据 `metadata.createTime` 换算为 `Asia/Shanghai` 的 `MMDD`，结合 `state.summary` / 现有标题提炼 `类型` 与 `主题`。
3. 传入 `--conversation-id <id>` 调用 `set-title.mjs` 完成更新（批量重命名前建议先向用户列出拟修改清单确认，或对未规范项逐条更新）。

## 示例

| 用户首条消息 | 规范标题 |
| :--- | :--- |
| 登录接口偶尔 500，帮我查下 | `1125｜修复｜登录接口超时` |
| 把设置页改成深色 | `1125｜设计｜设置页深色主题` |
| 加一个批量导出按钮 | `1125｜功能｜批量导出按钮` |
| 这个列表滚动很卡 | `1125｜优化｜列表滚动卡顿` |
| 提交代码到远端 | `1125｜发布｜代码提交远端` |
| 看下这个仓库的构建流程 | `1125｜探索｜构建流程梳理` |
| 补一下 README 的安装章节 | `1125｜文档｜安装章节补充` |
| 对比 zustand 和 jotai 怎么选 | `1125｜研究｜状态库选型对比` |
| hello / 你好（纯寒暄或测试） | `1125｜探索｜日常问候` |
